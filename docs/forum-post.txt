Hi everyone!

[b]x3ui[/b] is an open-source injected UI for X3: Albion Prelude and Terran Conflict on
Linux — a Dear ImGui overlay LD_PRELOADed into the running engine. It walks the engine's
live object graph out of process memory and renders the current sector as a sortable object
table and a 3D holographic map drawn from the game's own ship geometry, then writes back:
clicking an object sets your HUD target.

The game executable is never modified and nothing is patched on disk.

[img]https://raw.githubusercontent.com/FabricSoul/x3ui/main/docs/images/x3ui-overlay-in-flight.png[/img]

[img]https://raw.githubusercontent.com/FabricSoul/x3ui/main/docs/images/x3ui-3d-map.png[/img]

Those station, gate and asteroid shapes are real engine meshes, not icons — read out of the
game's resident model data and placed every frame from the live engine transform. The sphere
is your actual gravidar scanner range.

[b]Honest status: this is no longer in development.[/b] I ran out of time for it. The read
side, the 3D map and the target bridge work; the ship command menu and the player auto-dock
are unfinished prototypes. It's Linux-only and the launcher scripts still hardcode my paths.
Please fork rather than wait on an issue reply.

I'm mostly posting it for the reverse-engineering notes, which are probably more useful to
this forum than the overlay itself — the render pipeline (draw gates, LOD, the fixed-point
transform convention), the MSCI .pck codearray format so scripts can be hand-built without
the in-game editor, the script VM and task scheduler, and the ship command/autopilot
structures. All of it tagged for whether it was decompiled or confirmed live in flight.

Full feature list, build instructions, limitations and all the engine documentation are in
the README:

https://github.com/FabricSoul/x3ui
